## Upgrade notes

**lineup-gateway 0.6 has a new config format and refuses the 0.5 one at startup.** Rewrite `lineup-gateway.toml` from [`deploy/gateway.example.toml`](https://github.com/alexey-lapin/lineup/blob/main/deploy/gateway.example.toml) before upgrading the gateway image; check it first with `lineup-gateway --check-config --config <file>`. Keep the rule names and lineup routes need no changes: they resync on their own when the gateway's rule revisions change. Step by step: [docs/gateway.md](https://github.com/alexey-lapin/lineup/blob/main/docs/gateway.md#migrating-from-05).

lineup itself needs no migration: same database, same API, same CLI.

## lineup-gateway: rules from config

The gateway no longer knows any site. Each `[rules.<name>]` block is a rule lineup routes can use:

- **Kinds**: `relay` (extractors look the page up; the gateway relays its HLS), `link` (play URLs from a template, for streams behind another service) and `acestream` (an engine for names and checks).
- **Matching**: ordered patterns on the raw input or on host, path and query, typed captures, and templates for identity, ref and play. Examples in the config are checked on every load.
- **Extractors** are config too: command, arguments, output format (`yt-dlp-json`, `streamlink-json`, or `descriptor-json` for your own scripts) and timeouts. They run in a cleaned environment with all traffic through the egress proxy, and every output goes through one validator.
- **Revisions** are hashes of each rule's config, so editing a rule makes lineup resync it.
- Adding a site that yt-dlp or streamlink can play as HLS is a config block; see [docs/gateway.md](https://github.com/alexey-lapin/lineup/blob/main/docs/gateway.md).

Behaviour changes: Acestream checks are off unless `checks = true`; inputs with a user name or password, or over 4 KiB, are refused; a VK `video_ext.php` `hash` must look like a `list` token.

## lineup: no protocol names

lineup's server, CLI, API docs, web UI and docs no longer name any streaming protocol or site; that knowledge lives only in gateways. The legacy `/integrations` → `/routes` redirect in the web UI is removed.
