## Upgrade notes

**0.5 starts from a new database and needs a gateway for Acestream and VK.** It cannot open a 0.4 database: it refuses to start and leaves the file untouched. Acestream and VK support moved out of lineup into a gateway service (such as lineup-gateway). Export your playlists and records with 0.4, run a gateway, start 0.5 on an empty volume, add routes and re-import. Step by step: [docs/deploy.md](https://github.com/alexey-lapin/lineup/blob/main/docs/deploy.md#upgrading-from-04).

## Routes replace integrations

A **route** is how a channel is played, and you pick it when you add the channel; lineup no longer guesses from the URL.

- **Direct**: stream URLs, put in playlists as they are. A new database has this one.
- **Gateway** routes: a gateway's address and one of its rules (for example `acestream` or `vk`). The gateway validates what you paste, returns the canonical source and the play URL, and suggests a name, group and region for the guide match. Any number of routes, also several on one gateway.

lineup itself no longer knows any streaming protocol: Acestream id forms, engine name lookups, acexy's activity guard, the probe and VK link parsing all live in the gateway now. Playlists and guides never call a gateway; adding, editing and importing channels of a gateway route do, and fail (exit code 6 in the CLI) when it is down.

- **Routes** page: each route with its gateway's live status, the last resync, and Resync, Enable/Disable, Edit, Delete. Adding a route loads the gateway's rules from its address; any config can be tried with an input before saving.
- A disabled route keeps its channels listed and in their playlist positions, but out of playlists and guides.
- Changing a gateway route's address revalidates every channel first and changes nothing if any fails. Resyncs (manual, or automatic when the gateway reports a rule change) update play URLs in one step and never touch your names, groups or guide matches.
- Adding a link that matches an existing channel with a different access token (for example a new VK `list`) offers to update that channel's source.

## Checks

Checks are generic: the route's gateway checks the channel, when its rule supports it. Results can say what a broadcast is now (live, ended with the recording not ready, recording), and a finished broadcast is never "dead". The schedule moved to **Settings → Channel checks** (`check_interval_hours`, off by default). Channel details show what the gateway observes now.

## Guide: every channel shows up; event channels are gone

- The event flag and kickoff time are removed (database, API, CLI `--event/--kickoff`, web form and badge, the gateway's `event` hint). Old clients sending `is_event`/`kickoff_at` are accepted; the fields are ignored.
- Instead, a channel that no guide source covers gets its own name as hourly programmes on whole hours of the server's time zone (`TZ`), so it still appears in guides. Channels a source covers are unchanged.
- Renaming a channel now also announces `epg.updated`.

## Other changes

- Import takes a route; entries it does not accept are skipped and listed. A gateway failure during an import writes nothing.
- API: `/routes`, `/routes/test`, `/routes/{id}/status`, `/routes/{id}/resync` and `/checks` replace `/integrations/*` and `/probe`. Channels have `route_id`, `route_name`, `route_enabled`, `source` (a string), `identity` and `play_url` instead of the typed `source`, `source_key`, `stream_url` and `configured`. `POST /resolve` and `POST /import` take a `route_id`. Gateway failures answer 502 with the codes `gateway_unreachable`, `gateway_error` or `contract_mismatch`. UI events: `route.changed` replaces `integration.changed`, `channel.checked` replaces `channel.probed`.
- CLI: `lineup route ls|show|add|edit|rm|test|resync`, `lineup check` (was `probe`), `--route` on `add`, `resolve`, `import`, `ls` and `edit`; `lineup integration` is gone. Channels can be referred to by their stored source or identity. Exit code 6 means a gateway failed.
- New crate `gateway-contract`: the wire types and fixtures of gateway contract v1.
